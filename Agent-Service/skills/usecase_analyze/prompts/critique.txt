## 추가 critical 기준 (Mermaid/Use Case 특화)
- features의 필수 필드(summary, actor, basicflow 중 하나) 누락
- relatedVOS가 실제 존재하지 않는 키를 참조
- VOS 목록의 **절반 이상**이 어떤 Feature에도 매핑되지 않음
- document에 Context / Use Case / Sequence 다이어그램 중 **2개 이상 누락**
- Mermaid 코드블록 구문 오류 (열고 닫지 않음, 노드 참조 오류 등)
- **Use Case Diagram을 `classDiagram`으로 작성** (반드시 `graph TB`)
- **classDiagram 멤버에 한글/공백/대괄호 사용** (영문만 허용, label은 큰따옴표 필수)
- **Mermaid 노드 ID에 공백/한글 직접 포함** (영문/숫자만, 표시명은 `[]`/`(())`로 감쌀 것)
- **외부 이미지 참조로 다이어그램 대체** (모든 다이어그램은 ```mermaid 인라인 코드블록)
- **다이어그램 자체 누락**
- **Feature가 1건뿐**이고 VOS가 3건 이상 (과도 통합)
- **모든 Feature의 Actor가 동일**하고 다른 Actor 누락
- **큰 개념을 그대로 Use Case로 채택** (정상/비정상/예외 분해 없음)
- **Basic Flow 내부에 5단계 이상 상호작용**이 분리되지 않음
- **예외/대체 User Story 누락** (alternativeflow / exceptionflow가 전부 비어있거나 피상적)

## 판정 규칙
- `critical`이 비어있지 않으면 score 무관하게 `pass=false`
- `critical`이 비어있고 `score`가 검증 정책의 임계값 이상이면 `pass=true`
- `score`는 검증 기준 충족도의 종합 점수 (0.0~1.0)
- optional 필드 비어있음, 시나리오 간결함은 critical이 아닌 suggestions

## 출력 (반드시 JSON 객체로만 응답)
{{
  "score": 0.0~1.0 사이 실수,
  "pass": true 또는 false,
  "critical": ["치명적 결함 (없으면 빈 배열)"],
  "suggestions": ["개선 제안 (있을 때만)"],
  "reasoning": "판단 근거"
}}

## 작업

### Step 1. 추천 구조 결정
- Primary / Secondary / Supporting 을 자연스러운 조합으로 정리
- 서로 다른 scope 의 스타일은 **직교(orthogonal)** — 병행 채택 가능
- 동점(±3 이내) 후보가 있으면 결정적 차이를 서술

### Step 2. architecture/architecture-style.md 본문 작성

양식:

## 출력 (반드시 단일 JSON 객체)

{{
  "chosen": {{
    "primary": ["style-id", ...],
    "secondary": ["style-id", ...],
    "supporting": ["style-id", ...]
  }},
  "document": "전체 architecture-style.md 본문 (Markdown)"
}}

**주의**:
- `chosen.primary/secondary/supporting` 은 엔진 결과를 존중하되, 충돌/조합 해석에 따라 제한적으로 조정 가능
- 카탈로그에 없는 스타일 ID 사용 금지
- 문서 본문은 기계 번역체가 아닌 자연스러운 한국어 서술

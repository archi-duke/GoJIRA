# 기술 결정 이력

**목적**: "왜 이 기술을 썼는가", "왜 바꿨는가" 를 주제별로 찾을 수 있게 모은 문서.
**갱신**: 2026-11-16

## 읽는 법

- `docs/decisions/YYYY-MM-DD-decisions.md` 는 **날짜별 원본 로그**(D1~Dn)다. 결정 당일의 맥락과 미결 사항이 그대로 남아 있다.
- 이 문서는 그것을 **주제별로 묶은 색인**이다. 각 항목은 선택 → 이유 → 폐기한 대안 → 참조 순으로 적는다.
- 원본과 어긋나면 **원본이 정본**이다. 날짜별 로그와 설계서를 가리키는 참조를 항목마다 달았다.
- 폐기된 결정은 지우지 않는다. **왜 폐기했는지가 다음 판단의 재료**다.

## 1. 플랫폼 · 프론트엔드

### Module Federation 표준 = Vite + @module-federation/vite

**결정일**: 2026-07-06

**선택**: MF 빌드는 Vite 로 통일하고, singleton 은 `react` · `react-dom` · `@platform/web-ui` 셋만 둔다.
**이유**: 셸과 remote 가 서로 다른 번들러를 쓰면 공유 모듈 중복 인스턴스가 생긴다. singleton 을 최소로 묶어 React 컨텍스트 분열을 막는다.
**참조**: `decisions/2026-07-06` D4 · `design-microfrontend.md`

### 셸 인증 = MF expose + in-page 게시 (fetch monkey-patch 폐기)

**결정일**: 2026-07-06

**선택**: 셸이 `platformApp/auth` 를 expose 하고, 동시에 `window.__platformAuth` 로도 게시해 이중화한다.
**폐기한 것**: `fetch` 를 monkey-patch 해 토큰을 주입하는 방식.
**왜 바꿨나**: 전역 `fetch` 를 가로채면 remote 가 자기 요청에 무엇이 붙는지 알 수 없고, 디버깅이 불가능하다. 라이브러리가 자체 fetch 래퍼를 쓰면 주입이 조용히 빠진다.
**참조**: `decisions/2026-07-06` D10 (P2-A) · `platform-contract` 02

### 셸 ↔ remote 상태 공유 = 마운트 props + onNavigate 콜백

**결정일**: 2026-07-06

**선택**: 셸이 remote 에 props(`user`·`authority`·`page`·`resetKey`)를 주고, remote 는 `onNavigate(pageKey)` 로 활성 페이지를 보고한다.
**폐기한 것**: `sessionStorage` 에 magic string 을 써서 양쪽이 읽는 방식.
**왜 바꿨나**: 키 이름이 암묵적 계약이라 한쪽이 바꾸면 조용히 깨지고, 탭 간 간섭도 생긴다.
**참조**: `decisions/2026-07-06` D3 · D12 (P2-C)

### Remote = 바디 전용, standalone HTML 진입 폐지

**결정일**: 2026-07-07

**선택**: remote 는 바디만 렌더하고, 직접 접근은 셸로 302 수렴시킨다.
**이유**: standalone 진입을 함께 지원하면 레이아웃·인증·스타일을 두 경로로 유지해야 한다.
**참조**: `decisions/2026-07-07` D4

### 게이트웨이 경로 체계 v2 — 제품 프리픽스 단일화

**결정일**: 2026-07-07

**선택**: `/<제품>/...` 하나로 통일하고 `-app`·`-api` 접미사를 없앴다. 구 경로는 한시적 alias 로 남긴다.
**왜 바꿨나**: `-app`/`-api` 가 붙으면 제품이 늘 때마다 라우팅 규칙이 두 배가 된다.
**주의**: 구버전 런처(≤0.1.15)가 파생 URL 을 만들기 때문에 alias 를 바로 못 지운다. fleet 업데이트 후 제거.
**참조**: `decisions/2026-07-07` D16 · `deploy/images/gateway/locations.conf`

### React 19 상향 (플랫폼 표준 고수)

**결정일**: 2026-07-06

**선택**: 플랫폼 표준을 19 로 두고 RAGaaS 가 상향한다.
**이유**: React 18 remote 를 19 셸에 마운트하면 `ReactCurrentOwner` 크래시가 난다. 셸을 내리는 것보다 remote 를 올리는 쪽이 범위가 작다.
**참조**: `decisions/2026-07-06` D9

## 2. 인프라

### MongoDB · Gitea = shared-infra 로 이관

**결정일**: 2026-07-05

**선택**: RAGaaS 와 공유하는 `shared-infra` 스택에 두고, GoJIRA compose 에는 자체 빌드 앱만 남긴다.
**이유**: 같은 호스트에서 두 제품이 각자 Mongo 를 띄우면 자원과 백업이 중복된다.
**대가**: 인프라가 **다른 호스트에 있을 수 있다**는 전제가 생긴다. compose 에 컨테이너 이름을 하드코딩하면 그 환경에서 재기동 시 연결이 끊긴다 — 실제로 RAGaaS 에서 발생해 `${VAR:-기본값}` 변수화로 고쳤다.
**참조**: `decisions/2026-07-05` D1 · D2 · D3 · `shared-infra-handoff.md`

### 서버는 절대 commit / push 하지 않는다

**결정일**: 2026-07-04

**선택**: git 쓰기는 사용자 PC 의 런처만 수행한다. 서버는 읽기와 조회만.
**이유**: 서버가 커밋하면 작성자 신원이 서버 계정으로 뭉개지고, 사용자 권한 체계를 우회한다.
**참조**: `decisions/2026-07-04` D5

### git 자격 = 공용 PAT → 로그인 사용자 본인 PAT

**결정일**: 2026-10-20

**선택**: 런처가 Platform-API 에서 사용자 PAT 를 받아 쓴다.
**폐기한 것**: 공용 PAT 하나를 모든 런처가 공유.
**왜 바꿨나**: 공용 PAT 는 커밋 작성자를 가리고 보호 브랜치 규칙도 무력화한다. 같은 흐름에서 `force_merge` 상시 우회도 제거해 머지가 protection 을 준수하게 했다.
**참조**: 런처 v0.1.34 커밋

## 3. 에이전트 · 워크플로우

### LLM 벤더 종속 회피 — 단일 벤더 런타임 미채택

**결정일**: 미확인 (정책 결정)

**선택**: 자체 ReACT 루프를 유지한다.
**폐기한 것**: Claude Agent SDK 등 특정 벤더 런타임 채택.
**이유**: 사내 정책상 단일 벤더 런타임에 묶일 수 없다. `llm.json` 레지스트리로 멀티 프로바이더를 두고, Gemini 는 LiteLLM 프록시를 경유한다.
**참조**: `design-agent.md` · `Platform-API/llm/`

### DocGen(설계문서 생성) 제거, LLM 호출 인프라는 유지

**결정일**: 2026-07-04

**선택**: 서버가 문서를 생성하는 기능만 떼고 LLM 클라이언트는 남겼다.
**왜 바꿨나**: 문서 생성은 에이전트 스킬이 사용자 PC 에서 하는 쪽이 맞다. 서버 생성은 git 쓰기 금지 원칙과도 충돌했다.
**참조**: `decisions/2026-07-04` D4

### Agent-Service 폐기 → 조회는 웹, 편집은 VS Code 확장

**결정일**: 2026-05-22

**선택**: Python Agent-Service 를 통째로 제거하고, 편집 경험은 VS Code 확장으로 옮긴다.
**왜 바꿨나**: 웹에서 에이전트 세션을 중계하면 스트리밍·재연결·터미널을 전부 다시 만들어야 했다. 편집은 에디터가 이미 잘하는 일이다.
**남은 흔적**: `agent_sessions.messages[]` 기반 대화 저장이 함께 사라졌다. E7 성격의 협업 기록 패턴이 현재 없는 이유다.
**참조**: `Long-term Considerations/architecture-pivot-vscode.md` · 커밋 `89b379f9`

### 워크플로우 = 코드 State Machine + 결정적 조립

**결정일**: 2026-04-22 ~ 04-29

**선택**: 단계 전이는 코드가 판정하고(`project-status.sh` nextStage, `drift-check.py` stage hash), LLM 은 단계 내부 작업만 한다. 문서 조립은 `*-assemble.py` 가 결정적으로 수행한다.
**폐기한 것**: ReACT 단일 루프에 전 과정을 맡기는 방식.
**왜 바꿨나**: 단일 루프는 긴 체인에서 스톨하고, 같은 입력에 다른 산출을 냈다. 전환 후 4스킬 체인 109턴에서 **스톨 0회**, SATAM 은 reasoning 토큰 **-89%** · 턴 **-55%**, 문서 생성은 **5분 9초 → 9초**.
**함께 배운 것**: LLM 이 validator 를 **우회하는 법을 학습**한 사례가 있었다. 판정기를 더 엄격하게 하는 것으로는 막히지 않아 알고리즘을 재설계했다 — 검증 구조 자체가 우회 불가능해야 한다.
**참조**: `refactored-skills-evaluation.md` §9 · §12~14 · `skill-execution-time-analysis.md` · `tactics-for-skill.md`

### 다이어그램 = Mermaid → PlantUML

**결정일**: 2026-04-24

**선택**: use case · 배포 · 패키지 다이어그램은 PlantUML 로 생성한다.
**왜 바꿨나**: Mermaid 는 표현 한계가 있었고, LLM 이 자주 틀리는 문법 패턴이 반복됐다.
**보완**: 마크다운 안 PlantUML 블록의 흔한 LLM 실수 6종을 정규식으로 자동 교정하는 `plantuml-doc-fix` 를 만들어 `doc-save.sh` 에 연결했다 — LLM 호출 0회, 약 30ms.
**참조**: `plantuml-doc-fix` 스킬

### 에이전트의 임의 curl 억제 = `_scripts` 캡슐화

**결정일**: 미확인

**선택**: 조회·저장 계열을 스크립트로 감싸 에이전트가 직접 HTTP 를 부르지 않게 한다.
**폐기한 것**: env 차단, 프롬프트로 curl 금지.
**왜 바꿨나**: 금지만으로는 지켜지지 않았다. 호출 경로를 아예 제공하는 쪽이 확실하다.
**주의**: 스킬을 바꾸면 **런처 버전을 올려야** 배포된다. `assets/` 직접 수정은 다음 빌드에서 덮어써진다.

### 스타일 점수 = RAGaaS 지식그래프 조회 (Agent-Service 엔진 폐기)

**결정일**: 2026-11-16

**선택**: style-define Step 0.3.3 의 적합·회피 점수를 RAGaaS 조회 API(`agent/plan`)로 계산한다. 못 붙으면 로컬 카탈로그 YAML 을 같은 셈법으로 읽는 대체 경로로 내려간다.
**폐기한 것**: Agent-Service 의 `style_define` 엔진(`style-score.py` wrapper).
**왜 바꿨나**: 그 Agent-Service 가 커밋 `89b379f9`(2026-05-22)에서 제거돼 **반 년 가까이 exit 1** 이었고, 그동안 에이전트가 카탈로그를 눈대중으로 읽어 판단했다. 같은 카탈로그가 RAGaaS KB 에 지식그래프로 올라가 있어 조회만으로 같은 점수를 낼 수 있다 — LLM 호출 없이 0.4~0.9s.
**대가**: 점수가 외부 서비스에 의존한다. 그래서 출처를 2개로 두고 셈법을 한 곳(`satisfies` + `index.yaml` weights)에 모았다 — RAGaaS 와 로컬 YAML 이 점수·순위·근거까지 일치함을 NORM 2종으로 확인했다.
**범위**: 적합·회피 **신호만** 합산한다. 품질속성 가중·전제조건·조합 보너스는 넣지 않았다 — 조합 설계와 QA 가중 평가는 LLM 몫이고 점수는 참고용이라는 원칙(Step 2~3)을 유지했다.
**운영 주의**: RAGaaS `plan` 은 조건 **12개 초과 시 reject**, `in` 에 목록 밖 값이 하나 섞이면 **질의 전체가 zero** 다. 둘 다 스크립트가 흡수한다(분할 질의 + `describe` 허용값 선별). KB·주소는 `RAGAAS_STYLE_KB` · `RAGAAS_API` 로 바꾼다.
**참조**: PR #133 · `_scripts/style-score.py` (`--selftest`) · RAGaaS `skills/ragaas-query/SKILL.md`

## 4. 로컬 런처

### 런처 재정의 = 단일 진입점 + 로컬 서비스 플랫폼

**결정일**: 2026-11-05

**선택**: 진입점은 `http://127.0.0.1:5599` 하나로 두고, 런처 책임을 **배포(카탈로그·설치·업데이트) + 소환 + 라우팅** 으로 좁힌다. 기능은 독립 로컬 서비스가 제공하고 웹은 기능 경로(`/v1/docs/pptx/text`)로 호출한다.
**이유**: 사내 DRM 문서를 Office COM 으로 변환해야 하는데 서버에는 그 도구를 둘 수 없고 브라우저는 COM 에 접근할 수 없다. 런처에 직접 넣으면 이미 5개 책임이 섞인 런처에 제품 무관 기능까지 더해진다.
**참조**: `decisions/2026-11-05` D1 · D2 · `design-launcher-gateway.md`

### 카탈로그 서명 = 파이프라인 자동 서명 (담당자 수동 서명 폐기)

**결정일**: 2026-11-05

**선택**: main 머지 시 `build-catalog.sh` 가 검증 후 ed25519 자동 서명한다. 통제는 PR 리뷰(CODEOWNERS) + 보호 브랜치로 한다.
**왜 바꿨나**: 배포 빈도가 높아 수동 서명이 병목이 된다.
**보완**: `issuedAt` 역행 거부, `expiresAt`(30일) 주기 재서명, 런처 공개키 2슬롯(교체·유출 대응).
**참조**: `decisions/2026-11-05` D3 · D4 · D5

### 키 2종 분리 — 루트 키 / 카탈로그 키

**결정일**: 2026-11-05

**선택**: 런처 매니페스트는 루트 키로(environment 승인자 필수), 카탈로그는 카탈로그 키로 자동 서명한다.
**이유**: 런처는 공개키를 품은 신뢰 루트다. 그 자기 업데이트까지 자동 서명에 맡기면 파이프라인 침해가 전체 신뢰를 무너뜨린다.
**현재 상태**: 경고 모드(A). 공개키 슬롯이 비어 있어 검증 실패를 로그만 남긴다. 필수 모드(B) 전환은 GHES runner·키 구축 후.
**참조**: `decisions/2026-11-05` D5 · 이슈 #116

### 카탈로그 소스 / 게시본 분리

**결정일**: 2026-11-06

**선택**: 소스는 `deploy/launcher-catalog.json`(git 추적, 메타 없음), 게시본은 `deploy/launcher-dist/catalog.json`(gitignore, `stamp`·`sign` 산출물).
**왜 바꿨나**: 한 파일이 소스이면서 서빙 대상이라, 게시 날짜가 커밋에 섞이고 그걸 되돌리다 **`expiresAt=1970` 이 살아남아 런처가 카탈로그를 만료로 거부**하는 사고가 났다.
**함께 고친 것**: 메타 주입(`stamp`)을 서명에서 분리했다. 서명 키가 없는 경고 모드 동안에도 유효한 카탈로그를 만들 수 있어야 한다.
**참조**: PR #123

### 로컬 clone = 사용자별 경로 분리

**결정일**: 2026-10-20

**선택**: 작업본 경로에 사용자 ID 를 넣는다.
**왜 바꿨나**: 사용자를 전환하면 이전 사용자의 작업본이 섞였다.

### 자동 업데이트 = 실패 버전 기억 (클라이언트 자기 보호)

**결정일**: 2026-11-05

**선택**: 교체 직전 목표 버전을 기록하고, 재기동 후 버전이 오르지 않으면 그 버전을 건너뛴다.
**왜 넣었나**: 서버의 `version.txt` 와 실제 바이너리가 어긋나, 런처가 1초 간격으로 다운로드·교체·재시작을 **무한 반복**했다. sha256 이 맞으니 검증도 통과하고 교체도 성공해서 어디서도 멈추지 않았다.
**원칙**: 서버 배포본이 어떤 상태든 클라이언트가 무한 루프에 빠지면 안 된다. 서버 측 보호(부분 빌드 시 매니페스트 갱신 금지)도 함께 넣었지만, **클라이언트 보호가 더 중요하다** — 누가 무슨 실수를 하든 사용자 PC 가 망가지지 않아야 한다.
**참조**: PR #122

### Windows 에이전트 창 = Windows Terminal 우선 (conhost `cmd /k` 폐기)

**결정일**: 2026-11-15

**선택**: `wt.exe` 가 있으면 Windows Terminal 새 창의 PowerShell 에서 에이전트를 띄우고, 없거나 wt 기동이 실패하면 PowerShell 콘솔 창으로 폴백한다.
**폐기한 것**: `cmd /k "title … && chcp 65001 && <bin>"` 로 띄우던 conhost 창.
**왜 바꿨나**: conhost 에서는 `chcp 65001` 을 해도 에이전트 TUI 의 한글과 박스문자가 깨졌다. 폴백도 cmd 대신 PowerShell 로 바꿨다. npm 전역 CLI(`claude`)가 `claude.ps1` shim 으로 해석되므로 `-ExecutionPolicy Bypass` 가 필요하다.
**대가**: `wt.exe` 는 요청만 넘기고 바로 종료해서 env 블록도 실제 셸 PID 도 전달되지 않는다. 그래서 주입 env 를 임시 `.ps1`(UTF-8 BOM. PS 5.1 이 BOM 없는 파일을 CP949 로 읽기 때문)에 쓰고, `.ps1` 이 자기 `$PID` 를 파일로 보고하면 런처가 `OpenProcess` 로 추적한다. 세션 레지스트리와 과제전환 트리종료는 이 PID 로 동작한다.
**주의**: 임시 `.ps1` 에는 `GOJIRA_SESSION_TOKEN` 이 평문으로 들어간다. 스크립트가 실행 직후 자기 파일을 지우고, 20초 안에 PID 보고가 없을 때도 지운다. wt 가 없는 PC 의 폴백 경로는 실제로 띄워 보지 않았다.
**참조**: PR #131

## 반복되는 교훈

개별 결정을 넘어, 여러 사고에서 같은 형태로 되돌아온 것들이다.

**금지보다 경로 제공** — 에이전트의 임의 curl 을 프롬프트로 금지해도 지켜지지 않았다. `_scripts` 로 감싸 호출 경로를 주는 쪽이 확실했다. LLM 이 validator 를 우회한 사례도 같다. 규칙을 더 엄하게 쓰는 것보다 **우회가 구조적으로 불가능하게** 만들어야 한다.

**소스와 산출물을 섞지 말 것** — 카탈로그가 git 소스이면서 서빙 대상이라 게시 메타가 커밋에 섞였고, 되돌리다 가짜 메타가 남아 런처가 카탈로그를 거부했다. 산출물은 gitignore 로 분리한다.

**설정의 단일 진실을 파일에 둘 것** — RAGaaS 인프라 주소가 **어느 설정 파일에도 없고 3주 전 띄운 컨테이너에만** 있었다. 그 컨테이너를 한 번 재생성하면 복구 근거가 사라지는 상태였다. 동작하는 값은 반드시 파일에 있어야 한다.

**클라이언트는 서버를 신뢰하지 않는다** — 서버 매니페스트가 어긋나 런처가 무한 루프에 빠졌다. 서버 측 보호도 넣었지만, 누가 무슨 실수를 하든 **클라이언트가 스스로 멈출 수 있어야** 한다.

**조용한 실패를 남기지 말 것** — webhook 미등록(`CreateWebhook` silent skip), 게시본 누락(`404 "not found"` 뿐), 카탈로그 동기화 실패(로그만). 전부 "왜 안 되는지" 를 알 수 없어 추적에 시간이 걸렸다. 실패에는 사유와 조치를 함께 남긴다.

**측정 정의가 설계를 판단한다** — 지표 정의가 설계와 어긋나면 타당한 설계도 미달로 보인다. 설계 단위(청크)보다 세밀한 지표(문장)로 재면 설계가 하지 않는 일을 평가하게 된다.

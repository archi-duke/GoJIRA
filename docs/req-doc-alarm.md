# 프로젝트 알람 운영 정책

1. 알람은 접속한 사용자에게 서버 푸시로 전달되어 실시간으로 파악할 수 있게 한다.

2. 알람은 프로젝트 맵에서 프로젝트 그래프의 색상과 그래프의 프로젝트 이름 왼쪽에 배지를 달아 구분한다.

3. 알람의 종류와 발생 조건은 다음과 같다.

   **3.1 PR 요청**
   - `docs/public/icon/git-pull.svg`를 배지로 사용
   - 알람 색상은 `#27ae60`을 사용 (그래프, 텍스트, 배지 적용)
   - 발생 조건:
     Gitea에서 PR 발생 시, PR 이벤트를 발생하고 서비스는 이벤트를 수신하여
     해당 레포지토리를 사용하는 프로젝트의 상태를 처리한 후 접속한 사용자에게 서버 푸시로 알림을 전달.
     프론트엔드는 알림 수신하면 로그인 사용자가 해당 PR 리뷰어(Auditor)로 지정된 경우 알림을 UI에 반영
     (알림 발생 프로젝트를 오픈하여 사용하는 경우 컴포넌트 뷰의 프로젝트 이름 우측에 이벤트 배지를 지정한 색상으로 표시).

   **3.2 문서(자료)의 차이 발생**
   - `docs/public/icon/git-fetch.svg`를 배지로 사용
   - 알람 색상은 `tomato`를 사용 (그래프, 텍스트, 배지 적용)
   - 발생 조건:
     Gitea에서 레포지토리의 main에 변화가 발생한 경우 이벤트를 발생하고 서비스는 이벤트를 수신하여
     해당 레포지토리를 사용하는 프로젝트의 상태를 처리한 후 접속한 사용자에게 서버 푸시로 알림을 전달.
     프론트엔드는 알림 수신하면 프로젝트의 상태를 UI에 반영
     (알림 발생 프로젝트를 오픈하여 사용하는 경우 컴포넌트 뷰의 프로젝트 이름 우측에 이벤트 배지를 지정한 색상으로 표시).

4. 두 가지 알림이 동시에 발생한 경우 우선 발생한 이벤트를 가장 왼쪽으로 표시하고 색상도 가장 먼저 발생한 이벤트의 색상으로 한다.

5. 위의 상황에서 하나의 이벤트가 처리되고 나면, 그다음 발생한 이벤트 기준으로 표시한다.

6. **문서 차이(branchDiff) 판정 기준**

   브랜치가 main보다 단순히 뒤처진 상태(ancestor)와 사용자가 실제 변경한 상태를 구분한다.

   | 상태 | 판정 | 알람 |
   |------|------|------|
   | 사용자 브랜치가 main의 ancestor (변경 없이 뒤처짐) | diff 아님 | 없음 |
   | 사용자 브랜치에 main에 없는 커밋 존재 (실제 변경) | diff 있음 | 있음 |

   판정 방식: `git merge-base --is-ancestor docs/{userId} main`
   - true → 사용자 변경 없음, 알람 미발생
   - false → 사용자 실제 변경, 알람 발생

   이 판정은 두 경로에서 수행한다:
   - **초기 로드**: `GET /Project/alerts?user={userId}` API에서 서버가 판정하여 반환
   - **실시간**: Gitea main push webhook → SSE push → 프론트엔드가 트리 비교하여 알람 갱신

7. **PR 알림 대상 제한**

   PR 알림은 해당 PR의 리뷰어(Auditor)로 지정된 사용자에게만 표시한다.
   - webhook 이벤트의 `requested_reviewers` 목록 기준
   - DB에 `gitOpenPRReviewers` 배열로 저장하여 alerts API에서 필터링

GitHub 기반 협업 문서 시스템 설계 요약

작성일: 2026-04-04 12:08
⸻
1. 개요

여러 사용자가 동시에 문서를 편집하고 변경 이력 및 승인 과정을 관리하기 
위해 GitHub 기반 협업 시스템을 설계한다.
⸻
2. 기본 협업 흐름

1. 사용자가 시스템에 로그인
2. 문서 편집 시작 시 자동으로 개인 브랜치 생성
    - 예: feature/{userId}/{docId}
3. 사용자는 해당 브랜치에서 작업 수행
4. 작업 완료 후:
    - 저장 → commit → push
5. 시스템이 자동으로 PR(Pull Request) 생성
6. 승인자가 리뷰 후 merge
7. main(or develop)에 반영
⸻
3. 서버 아키텍처 개념

- 서버는 GitHub과 인터페이스하는 API 제공
- 주요 역할:
    - 브랜치 생성
    - 변경 내용 commit
    - push 수행
    - PR 생성
    - PR 상태 조회

처리 방식

- 사용자별 작업 브랜치 관리
- 서버 내부에서 Git CLI 또는 GitHub API 활용
⸻
4. 동시 작업 처리 전략

- 사용자별 독립 브랜치 사용
- 충돌은 PR 단계에서 해결
- Git 기반 버전 관리 활용
⸻
5. 사용자 UX 흐름

편집 시작

- 로그인 후 문서 열기 → 자동 브랜치 생성

작업 중

- 실시간 편집
- 로컬 상태 유지 (서버 or 클라이언트 캐시)

저장 시

- 명시적 저장 버튼 제공
- 동작:
    - commit
    - push
    - PR 생성
⸻
6. 미완료 작업 처리

사용자가 저장하지 않고 종료한 경우:

다음 로그인 시: - "이전에 작업하던 내용이 있습니다. 이어서 
진행하시겠습니까?"

선택 옵션: - 이어서 작업 - 폐기
⸻
7. 설계 핵심 포인트

- Git = 단일 소스 오브 트루스
- PR = 승인 및 배포 프로세스
- 브랜치 = 작업 단위
- 사용자 경험 중심 자동화
⸻
8. 향후 확장

- Git Graph 시각화
- 변경 diff UI 제공
- LLM 기반 변경 요약
- 자동 리뷰 보조 기능
⸻
9. 요약

- 사용자 → 브랜치 생성 → 작업 → commit/push → PR → 승인 → merge
- 미저장 작업은 복구 가능하게 설계
- GitHub을 협업 엔진으로 활용
